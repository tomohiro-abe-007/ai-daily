Microsoft Build 2026 ──
Windows が「AI エージェント基盤」に変わる
Microsoft
🌱 やさしく解説
2026年6月2日、Microsoftの年次開発者向けイベント「Build 2026」が開幕しました。最大の発表は2つ。①自社開発のAI「Project Polaris（プロジェクト・ポラリス）」が2026年8月からGitHub Copilotの中心エンジンになること、②Windowsに「Windows Agent Framework（エージェント・フレームワーク）」を組み込み、AIエージェントが普通のアプリと同じようにWindowsで動けるようにすること。MicrosoftがOpenAIへの依存をやめ、自社AIへの切り替えを本格化させた歴史的な発表です。

  • 1 Project Polarisは「OpenAI脱却」の象徴 ── MicrosoftはOpenAIへ多額投資をしているが、GitHub Copilotの中核エンジンを自社製に変えることで、API費用を削減しつつ開発速度を自社でコントロールできるようになる
  • 2 Windowsが「AIエージェントが住む場所」に ── WAF v1.0はMITライセンスで公開。エージェントはアプリのように「Windows Agent Store（エージェントの配布場所）」で配布できる仕組みも整備される
  • 3 Azure Agent Mesh：複数AIが協力して仕事をする ── 「Azure Agent Mesh（エージェント・メッシュ）」は、複数のAIエージェントが役割分担しながら大きなタスクを完成させるための基盤。「プロジェクト管理AI」「コード生成AI」「テストAI」が連携するようなシステムが作れる
  • 4 MAI モデルファミリーが拡張 ── MAI-Image-2.5（画像理解）、MAI-Voice-2（音声）、MAI-Transcribe-1.5（書き起こし）が Microsoft Foundry 経由で正式公開予定（価格・GA日程は公式で要確認）
  • 5 Office 365にもAgent Modeが登場 ── Word・Excel・Teamsなどのビジネスツールで「AIエージェントモード」が使えるように。単なる補助ツールではなく、自律的にタスクをこなすAIがOfficeの中に入ってくる

GitHub Copilot 従量課金化 ──
開発者に「10〜50倍の費用増」ショック
開発ツール・料金
🌱 やさしく解説
2026年6月1日、AIコード補助ツールの定番「GitHub Copilot（ギットハブ・コパイロット）」が、料金の仕組みを大きく変えました。今まで「月1,200円（Pro）で使い放題」だったのが、使った量（トークン数）に応じて課金される方式に変わったのです。普通に使う人はほぼ影響なしですが、AIに自律的に大量の作業をさせる「エージェント的な使い方」をする開発者は月額費用が10倍〜50倍に跳ね上がるケースも報告されており、開発者コミュニティで大きな反発が起きています。

  • 1 「無制限」から「クレジット制」へ ── なぜ変えたのか ── AIエージェントが一度のセッションで数百万〜数千万トークンを消費するケースが増えたため、GitHubは「使った分だけ払ってもらう」方式に移行。企業として採算を取るための合理的な判断だが、ユーザーからは不満の声
  • 2 社会的な反発が広がっている ── TechCrunchの見出し「What a joke（笑えない）」など、開発者コミュニティで強い批判が続出。特に「フォールバックモデル（安いモデルへの切り替え）が廃止された」点も不満の原因
  • 3 企業ユーザーへの影響が深刻 ── Business・Enterpriseプランで多数の開発者が重いエージェント作業をする場合、月額費用が予測不可能なレベルに膨らむ可能性がある。予算管理の観点から、利用制限や代替ツール検討に動く企業も
  • 4 Project Polaris切り替えとの関係 ── 同じく6月2日に発表されたProject Polarisは「Maia AIアクセラレータを使ってコスト削減」を謳っている。コスト構造を変えながら収益モデルも変えるという、MicrosoftのAI事業の大転換が同時進行中
  • 5 競合への乗り換えが加速する可能性 ── CursorやCline、Windsurf等の競合AIコーディングツールへの移行を検討する開発者の声が増加。「AIコーディングツール市場の勢力図が変わるきっかけになる」との見方も

  • 2 「550B/55B」のMoE設計が省エネの鍵 ── 全部で5,500億個のパラメーターを持つが、一度の推論では550億個だけが動く。使わない部分は眠っているため、実際の計算量は10分の1程度で済む。高性能かつ高速（300+ tokens/秒）を両立
