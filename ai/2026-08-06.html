MCPって何？
── AIとツールをつなぐ「共通プラグイン規格」
技術解説
🌱 やさしく解説
MCP（エムシーピー）とは「Model Context Protocol（モデル・コンテキスト・プロトコル）」の略で、AIと外部ツール（カレンダー・データベース・コード実行環境など）を結びつけるための共通ルールのことです。Anthropicが2024年に提案し、2025〜2026年にかけてClaude・GPT・Geminiなど主要AIが対応するデファクトスタンダード（事実上の業界標準）になりました。「プロトコル（protocol）」とは、コンピューター同士が会話するときに使う「共通語のルール」です。（出典：Model Context Protocol公式ブログ / Wikipedia "Model Context Protocol"・2026年）
  • ① 「USB規格」に例えると分かりやすい
    昔のパソコン周辺機器はメーカーごとに接続方式がバラバラで、対応ドライバーを別々に用意する必要がありました。USBが登場してから「どのメーカーの製品でも同じ口でつなげる」ようになりました。MCPはそれと同じ考え方で、「どのAIモデルでも、どのツールでも、MCPというひとつの規格でつなげる」しくみです。開発者は1回MCPに対応すれば、多くのAIから使ってもらえます。（出典：The Register – "Model Context Protocol prepares to break with its stateful past"・2026年7月）
  • ② 2026年7月28日に「最大規模の仕様更新」が公開
    MCPのオープンソースプロジェクトが、2026年7月28日付けで「2026-07-28仕様（スペック）」を正式リリースしました。MCPが登場してから最大規模の改訂とされています。中心的な変更は「ステートレス化（stateless）」と呼ばれる構造の刷新で、その意味と影響が業界で大きく注目されました。（出典：Model Context Protocol公式ブログ – "The 2026-07-28 Specification"・2026年7月28日）
  • ③ 正式リリース前から「リリース候補（RC）」で事前告知
    今回の仕様変更は突然ではなく、正式公開の前に「リリース候補（RC：Release Candidate）」が公開されてコミュニティで議論されました。古い仕様（2024-11-05版や2025-03-26版）で作られたMCPサーバーと新仕様クライアントの間には互換性の問題が生じるため、段階的な移行が求められています。廃止（deprecated）となった機能は最低12ヶ月は動作し続ける予定です。（出典：Model Context Protocol公式ブログ – "The 2026-07-28 Specification"・2026年7月28日）
✏️ 中学生的に言うと：「MCPはAIとツールをつなぐUSBのような共通規格。2026年7月28日に誕生以来最大の仕様更新が公開された。新旧の仕様間には互換性の問題があり、段階的な移行が必要。」
📎 出典： Model Context Protocol 公式ブログ – "The 2026-07-28 Specification"（2026年7月28日） / The Register – "Model Context Protocol prepares to break with its stateful past"（2026年7月） / Wikipedia – "Model Context Protocol"

何が変わった？
── 「ステートレス化」のしくみをやさしく解説
アーキテクチャ変更
🌱 やさしく解説
「ステートレス（stateless）」とは「状態を持たない」という意味です。以前のMCPはAIとツールが会話を始めるとき「セッション（session）」という"つながり"を開始して、ずっと同じサーバーと話し続ける必要がありました。新仕様では「セッションなし・毎回独立した問い合わせ」に変わりました。スマホで例えると、旧方式は「電話をかけてつながったまま話し続ける」方式、新方式は「LINEのメッセージを1通ずつ送る」方式に近いイメージです。（出典：Digital Applied / MCP.Directory・2026年）
  • ① 「初期化ハンドシェイク」がなくなった ── つながるたびの挨拶を廃止
    旧仕様では、AIとMCPサーバーが通信を開始するとき「initialize（イニシャライズ）」という初期化の手続きをしてセッションIDを交換していました。新仕様ではこの初期化ハンドシェイク（握手のような確認手続き）が廃止されました。クライアント情報や対応機能は、毎回の問い合わせの「_metaフィールド」に一緒に含めて送る方式になりました。（出典：flaviocopes.com – "MCP is now stateless: what the 2026-07-28 update changes"・2026年 / Digital Applied・2026年）
  • ② 「セッションID」が廃止 ── 同じサーバーと話し続ける必要がなくなった
    旧仕様では「Mcp-Session-Id（セッションID）」というヘッダーを使い、最初に接続したサーバーと同じインスタンス（実体）で会話を続ける必要がありました（「スティッキーセッション」と呼ばれる仕組み）。新仕様ではセッションIDが廃止され、どのサーバーインスタンスが問い合わせに答えてもよくなりました。これにより一般的なロードバランサー（負荷分散装置・複数のサーバーに処理を振り分ける装置）の後ろにMCPサーバーを普通に置けるようになりました。（出典：Model Context Protocol 公式ブログ・2026年7月28日 / Appwrite・2026年）
  • ③ そのほかの主な追加・変更点
    ステートレス化以外にも今回の仕様更新にはいくつかの変更が含まれています。「マルチラウンドトリップリクエスト（複数回のやりとりを1つのリクエストにまとめる仕組み）」の追加、キャッシュ（一時保存）可能なリスト結果の導入、ヘッダーベースのルーティング（接続先の振り分け）、認証・認可（アクセス権の確認）の強化、そして公式の拡張フレームワーク（将来の機能追加のしくみ）の整備などが含まれています。（出典：Model Context Protocol 公式ブログ – "The 2026-07-28 Specification"・2026年7月28日 / modelcontextprotocol.io/specification/2026-07-28/changelog）
📞 旧仕様（ステートフル）
・接続時に「初期化ハンドシェイク」が必要
・セッションIDを使い同じサーバーと話し続ける
・ロードバランサーで複数サーバーに分散できない
・サーバーレス環境への導入が困難
（出典：Appwrite・2026年 / Digital Applied・2026年）
💬 新仕様（ステートレス・2026-07-28）
・ハンドシェイクなし・毎回独立したリクエスト
・セッションID廃止・どのサーバーでも応答可
・普通のロードバランサーで負荷分散できる
・サーバーレス・エッジ環境にも展開しやすい
（出典：Model Context Protocol 公式ブログ・2026年7月28日）
✏️ 中学生的に言うと：「旧MCPは『電話をかけてつながったまま』の方式。新MCPは『LINEを1通ずつ送る』方式。セッションIDという"つながり番号"が廃止され、複数のサーバーで処理を分担しやすくなった。」

なぜ重要？
── AIエージェント時代の「インフラの変革」
影響・意義
🌱 やさしく解説
「AIエージェント」とは、人が指示を出すとAIが自分でツールを呼び出したり、複数の作業を組み合わせたりして目標を達成するしくみのことです。2026年現在、こうしたAIエージェントは急速に普及しています。MCPがステートレス化したことで、AIエージェントが使うツールのサーバーを「普通のウェブサービス」と同じように大規模に運用できるようになりました。これはAIエージェントを本番環境（実際のサービス）に安定して展開するための重要な基盤整備です。（出典：Digital Applied・2026年 / Microsoft Community Hub・2026年）
  • ① サーバーレス・エッジ環境への展開が可能になった
    「サーバーレス（serverless）」とは、サーバーを常時起動させておかずに必要なときだけ処理を実行する方式です（AWS Lambda・Cloudflare Workersなどが代表例）。旧仕様のセッション管理が必要な構造では、こうした環境への導入が非常に難しい状態でした。新仕様ではMCPサーバーをサーバーレス環境やエッジ（利用者の近くに分散した小さなサーバー）に普通に置けるようになりました。この変更はMCPの普及を大きく後押しすると見られています。（出典：Microsoft Community Hub – "MCP Just Went Stateless"・2026年 / Digital Applied・2026年）
  • ② 大規模サービスでの利用がしやすくなった
    旧仕様では「スティッキーセッション（同じユーザーの問い合わせを必ず同じサーバーが担当する仕組み）」が必要でした。これはサーバーの台数が増えるほど管理が複雑になる問題がありました。新仕様ではどのサーバーインスタンスがどの問い合わせに答えてもよくなったため、ラウンドロビン（均等に振り分ける）などの一般的なロードバランシングをそのまま使えます。利用者が急増しても、サーバーを追加するだけで対応できるスケーラビリティ（拡張しやすさ）が向上しました。（出典：Appwrite・2026年 / Digital Applied・2026年）
  • ③ 互換性の問題に注意が必要
    今回の変更は大きな刷新であるため、旧仕様（2024-11-05版・2025-03-26版）で作られたMCPサーバーと、新仕様（2026-07-28）のクライアントは互換性の問題が生じる場合があります。公式は「どちらかが意図的なフォールバック（後方互換のための切り替え）や変換機能を実装しない限り、同じプロトコル時代を共有している必要がある」と説明しています。廃止とマークされた機能は最低12ヶ月は動作し続ける予定ですが、MCPを使った製品やサービスの開発者は移行作業が求められます。（出典：Model Context Protocol 公式ブログ・2026年7月28日 / stacktr.ee・2026年）

MCPとはAIとツールをつなぐ共通規格
Anthropicが提唱し、Claude・GPT・Geminiなど主要AIが対応。「AIのためのUSB規格」とも呼ばれる業界標準。
🔄
「ステートレス化」が最大の変更点
セッションID・初期化ハンドシェイクを廃止。毎回独立したリクエスト方式（LINEのメッセージ1通ずつ方式）に刷新。
🚀
サーバーレス・大規模展開が容易に
ロードバランサーやサーバーレス環境に普通のウェブサービスと同じように展開でき、AIエージェントの本番運用を後押し。
⚠️
旧仕様との互換性に注意
旧仕様のMCPサーバーと新仕様クライアントは互換性の問題が生じる場合がある。廃止機能は最低12ヶ月動作保証。
